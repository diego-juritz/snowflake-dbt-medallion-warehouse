# Data dictionary

Types are as created in Snowflake by the reference run. All amounts are in a
single unspecified currency. All data is synthetic; emails use the reserved
`example.com` / `example.org` / `example.net` domains.

## Sample data and intentional edge cases

Generated by [`scripts/generate_sample_data.py`](../scripts/generate_sample_data.py)
(fixed random seed, integer-cent arithmetic, no wall-clock values). Running it
again reproduces the files byte for byte (`--check` verifies this).

| File | Rows | Grain |
|---|---|---|
| `customers.csv` | 34 | one row per exported record (30 customers) |
| `products.csv` | 15 | one row per product |
| `orders.csv` | 80 | one row per order (2025-01-03 … 2025-11) |
| `order_items.csv` | 189 | one row per order line |
| `payments.csv` | 89 | one row per payment event |

| Edge case | Where | Handling |
|---|---|---|
| Duplicate customer records (C005 ×2, C012 ×2, C020 ×3) | customers | Type 1 dedup: latest `updated_at`, tie → highest `_record_id` |
| Exact `updated_at` tie (C012) | customers | deterministic tie-breaker on `_record_id` |
| Leading/trailing spaces, lower/upper-case names and emails | customers | `trim`, `initcap` with `' -` delimiters, `lower(email)` |
| Name with apostrophe (`O'Brien`) | customers | `initcap(…, ' ''-')` keeps `O'Brien` (see [validation report](validation_report.md#issues-found-and-fixed)) |
| Missing phone (8 customers) / country (2) | customers | NULL in Silver; `country_code = 'UNKNOWN'` in `dim_customers` |
| Lower-case country (`es`) | customers | `upper()` |
| Inconsistent category casing / padding | products | `initcap(trim())` |
| Missing category (P013) | products | NULL in Silver → `Uncategorized` in Gold |
| `is_active` as `true` / `TRUE` / `True` / `false` | products | `try_to_boolean` |
| Discontinued product (P012) still sold Jan–Mar (6 lines) | products / items | kept; `is_active = false` describes today, not the sale |
| 10 order status spellings (`Completed`, `complete`, `canceled`, ` pending` …) | orders | mapped to `completed` / `pending` / `cancelled`; others → `unknown` (fails test) |
| Mixed date format (`YYYY/MM/DD` on O0017, O0034, O0051, O0068) | orders | two explicit `try_to_date` formats; anything else → NULL (fails test) |
| Orphan order O0047 → customer C999 | orders | kept, flagged in `int_order_exceptions`, linked to Unknown customer |
| Multi-line orders (57 of 80) | items | aggregated to order grain before joins |
| Line discounts (31 lines) | items | subtracted for net sales |
| Failed attempt then success (8 completed orders) | payments | failed never counts as paid |
| Split tender: gift card + other method (8 orders) | payments | summed at order grain |
| Cancelled after payment, fully refunded (2 orders) | payments | net paid 0; no recognized sales |
| Cancelled with only failed attempts (3) / no payment (3) | payments | net paid 0 |
| Pending order with pending payment (1) / no payment (6) | payments | not paid; outstanding > 0 |
| Payment method spellings (`Credit Card`, `CREDIT_CARD`, `PayPal` …) | payments | `replace(lower(trim()), ' ', '_')` |

## Bronze (`BRONZE`, tables, source `bronze`)

`raw_customers`, `raw_products`, `raw_orders`, `raw_order_items`,
`raw_payments`: columns identical to the CSV headers, every column `VARCHAR`.
Each has `_record_id` (position in file), `_source_file`, and `_extracted_at`
(fixed simulated export timestamp, **not** a load time). Source tests: primary
keys `unique` + `not_null` (customers: `_record_id` unique, `customer_id` not
null, since duplicates are expected).

## Silver (`SILVER`, views)

### stg_customers — one row per raw customer record

| Column | Type | Meaning / transformation |
|---|---|---|
| source_record_id | NUMBER | `_record_id`; unique; dedup tie-breaker |
| customer_id | VARCHAR | business key, `upper(trim())` |
| first_name, last_name | VARCHAR | `initcap(trim())`, apostrophe/hyphen aware; blank → NULL |
| email | VARCHAR | `lower(trim())`; blank → NULL |
| phone | VARCHAR | optional; blank → NULL |
| country_code | VARCHAR | ISO alpha-2, `upper()`; blank → NULL |
| signup_date | DATE | `YYYY-MM-DD` |
| source_updated_at | TIMESTAMP_NTZ | source last-modified; dedup order key |
| source_file | VARCHAR | lineage |
| source_extracted_at | TIMESTAMP_TZ | simulated export time |

### stg_products — one row per product

| Column | Type | Meaning |
|---|---|---|
| source_record_id | NUMBER | lineage |
| product_id | VARCHAR | business key |
| product_name | VARCHAR | trimmed |
| category | VARCHAR | `initcap(trim())`; NULL if missing |
| list_price | NUMBER(12,2) | current catalog price, ≥ 0 |
| is_active | BOOLEAN | currently sellable |
| source_file, source_extracted_at | VARCHAR, TIMESTAMP_TZ | lineage |

### stg_orders — one row per order

| Column | Type | Meaning |
|---|---|---|
| source_record_id | NUMBER | lineage |
| order_id | VARCHAR | business key |
| customer_id | VARCHAR | as sent; may not exist (warn / strict error) |
| order_date | DATE | from `YYYY-MM-DD` or `YYYY/MM/DD` |
| order_status | VARCHAR | `completed` / `pending` / `cancelled` (`unknown` fails tests) |
| raw_status | VARCHAR | lower-cased trimmed source value, for audit |
| tax_amount | NUMBER(12,2) | order-level tax |
| source_order_total | NUMBER(12,2) | total stated by source; reconciled by test |
| source_file, source_extracted_at | VARCHAR, TIMESTAMP_TZ | lineage |

### stg_order_items — one row per order line

| Column | Type | Meaning |
|---|---|---|
| source_record_id | NUMBER | lineage |
| order_item_id | VARCHAR | business key |
| order_id, product_id | VARCHAR | FKs (tested) |
| quantity | NUMBER | ≥ 1 |
| unit_price | NUMBER(12,2) | price charged on the line |
| discount_amount | NUMBER(12,2) | 0 when absent |
| gross_sales_amount | NUMBER(38,2) | `quantity × unit_price` |
| net_sales_amount | NUMBER(38,2) | gross − discount, ≥ 0 |
| source_file | VARCHAR | lineage |

### stg_payments — one row per payment event

| Column | Type | Meaning |
|---|---|---|
| source_record_id | NUMBER | lineage |
| payment_id | VARCHAR | business key |
| order_id | VARCHAR | FK to orders (tested) |
| payment_method | VARCHAR | `credit_card` / `paypal` / `bank_transfer` / `gift_card` |
| payment_status | VARCHAR | `success` / `pending` / `failed` / `refunded` |
| amount | NUMBER(12,2) | > 0; refunds are positive and subtracted downstream |
| payment_date | DATE | event date |
| source_file | VARCHAR | lineage |

### int_customers_deduplicated — one row per customer_id

Columns of `stg_customers` (minus lineage) plus `winning_source_record_id`
(the record that won) and `source_record_count` (raw records merged).

### int_payments_by_order — one row per order with ≥ 1 payment event

`payment_event_count`, `amount_captured` (Σ success), `amount_refunded`,
`amount_pending`, `amount_failed`, `net_amount_paid` (captured − refunded),
`failed_payment_count`, `payment_methods` (distinct, comma-separated),
`first_payment_date`, `last_payment_date`.

### int_orders_enriched — one row per order

Order header plus line aggregates (`item_count`, `total_quantity`,
`gross_sales_amount`, `discount_amount`, `net_sales_amount`), recomputed
`order_total_amount` (net + tax), payment aggregates (zero-filled for orders
without payments), `has_valid_customer`, `is_revenue_recognized`
(`order_status = 'completed'`), and derived `payment_status`:
`refunded` (refunds > 0 and net paid = 0) → `paid` (net paid ≥ total) →
`partially_paid` → `payment_pending` → `unpaid`.

### int_order_exceptions — one row per (order_id, exception_type)

| Column | Type | Meaning |
|---|---|---|
| order_id | VARCHAR | flagged order |
| exception_type | VARCHAR | `orphan_customer`, `unparseable_order_date`, `unknown_order_status`, `order_without_items`, `total_mismatch` |
| detail | VARCHAR | human-readable explanation |

Current content: one row, `O0047 / orphan_customer`.

## Gold (`GOLD`, tables)

### dim_customers — one row per customer + Unknown member (31 rows)

| Column | Type | Meaning |
|---|---|---|
| customer_key | VARCHAR | MD5 surrogate of `customer_id` |
| customer_id | VARCHAR | business key; `-1` = Unknown customer |
| first_name, last_name, full_name | VARCHAR | cleaned names |
| email, phone | VARCHAR | contact (synthetic) |
| country_code | VARCHAR | ISO alpha-2 or `UNKNOWN` |
| signup_date | DATE | |
| source_record_count | NUMBER | raw records merged (0 for Unknown) |
| is_unknown_member | BOOLEAN | true only for `-1` |

### dim_products — one row per product (15 rows)

`product_key` (MD5 of `product_id`), `product_id`, `product_name`, `category`
(`Uncategorized` if missing; accepted values tested), `list_price`, `is_active`.

### dim_date — one row per day, 2024-01-01 … 2026-12-31 (1,096 rows)

`date_key` (NUMBER `YYYYMMDD`), `date_day`, `calendar_year`,
`calendar_quarter`, `calendar_month`, `month_short_name`, `year_month`
(`YYYY-MM`), `month_start_date`, `iso_day_of_week` (1 = Mon), `day_short_name`,
`is_weekend`. The range comes from the vars `dim_date_start` / `dim_date_end`.

### fct_orders — one row per order (80 rows)

| Column | Type | Meaning |
|---|---|---|
| order_key | VARCHAR | MD5 surrogate of `order_id` |
| order_id | VARCHAR | business key |
| customer_key | VARCHAR | FK → `dim_customers` (Unknown member for orphans) |
| source_customer_id | VARCHAR | customer id as received |
| has_valid_customer | BOOLEAN | false for orphans |
| order_date_key | NUMBER | FK → `dim_date` |
| order_date | DATE | |
| order_status | VARCHAR | completed / pending / cancelled |
| is_revenue_recognized | BOOLEAN | completed only; **filter on this for sales** |
| payment_status | VARCHAR | derived (see above) |
| item_count, total_quantity | NUMBER | |
| gross_sales_amount, discount_amount, net_sales_amount | NUMBER(38,2) | merchandise measures |
| tax_amount | NUMBER(12,2) | |
| order_total_amount | NUMBER(38,2) | net + tax (order value) |
| amount_captured, amount_refunded, net_amount_paid | NUMBER | payment measures |
| outstanding_amount | NUMBER | total − net paid; 0 for cancelled |
| failed_payment_count | NUMBER | declined attempts |
| payment_methods | VARCHAR | distinct methods used |

### fct_order_items — one row per order line (189 rows)

`order_item_key`, `order_item_id`, `order_key` (FK → `fct_orders`),
`order_id`, `customer_key`, `product_key`, `order_date_key` (FKs tested),
`order_status`, `is_revenue_recognized`, `quantity`, `unit_price`,
`gross_sales_amount`, `discount_amount`, `net_sales_amount`. No tax or
payment columns (order grain only).

## Known limitations

- Customers are Type 1: history such as C005's previous country is lost.
- Tax is not allocated to lines; category-level reporting is pre-tax.
- `is_active` and `list_price` are current values, not values at sale time.
- A single currency is assumed; there is no FX handling.
